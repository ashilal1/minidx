## 実装: エンドツーエンドで動作（初回）

- **やったこと**: 環境構築（Python 3.12 / uv）〜 取込 〜 検索 〜 二段ゲート 〜 生成 〜 CLI を実装。
  実物の旅費規程1本で質疑応答が成立した。
- **実物に合わせた設計変更**（すべて実測で判明）:
  1. 条文は `第 １ 条` と全角数字＋空白が混在。**NFKC正規化＋空白除去してから**境界判定しないと0件検出
  2. 条見出しは `第N条（見出し）` ではなく**直前の独立行**にある
  3. 金額は本文になく**表**にある。表チャンクに所属条文の文脈を付与しないと検索に上がらない
  4. 表は行単位ではなく**表単位**チャンク。行単位だと1行しか渡らず金額が揃わない
  5. JSON Schema の**フィールド宣言順が生成順**になる。`sufficient` を先頭に置くと
     回答を作る前に判断してしまい false が頻発した。引用→回答→判定の順に変更
  6. **逐語引用（quote）による照合は成立しない**。qwen2.5:7b は離れた箇所を「…」で連結するため
     部分文字列照合が落ちる。実装して実際に `rejected_bad_citation` を踏んだ。
     → **JSON Schema の enum で実在IDのみに制約**する方式へ変更。
     存在しない引用が文法的に生成不可能になり、出力トークンも約6割減る
  7. `num_ctx` 8192 では `ollama ps` が 12%/88% CPU/GPU（メモリ不足でCPUに落ちる）。
     4096 にすると 100% GPU に戻った
- **決めたこと**: 関連性の検証は「**回答中の金額が引用条文に実在するか**」が担う。
  **限界を明記**: 同一の表の中で行を取り違えた場合は、どちらの金額も表に実在するため検出できない。

  - 分離マージン: 回答可能8問の最小cos 0.623 / 回答不能8問の最大cos 0.566 → **+0.057 で分離可能**。
