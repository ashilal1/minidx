# 評価セット

MVPの合否は実装完了ではなく、ここで測る数値で判定する（`docs/MVP要件定義.md` §5）。

## ディレクトリ

```
eval/
├── negative/themes.yaml   回答不能質問のテーマ（30テーマ / 手書き90問）
├── positive/              回答可能質問。★規程ファイル受領後に作成（正解条文の特定が必要）
└── (生成物)               calib.jsonl / holdout.jsonl / bulk.jsonl
```

## 校正セットとホールドアウトの分離（最重要の運用ルール）

**同じ質問セットで閾値を決めて、同じセットで測ってはならない。**
回答不能質問の最大スコアのすぐ上に閾値を置けば、誤回答0件は定義上必ず達成できる。
それは「0%を達成した」のではなく「そうなるように置いた」だけで、数値に情報量がない。

| セット | 用途 | 見てよい回数 |
|---|---|---|
| `calib` | 閾値（τ_cos 等）の決定。分布の確認 | 何度でも |
| `holdout` | 最終的な実測 | **一度だけ** |
| `bulk` | 誤通過率の上限推定 | 何度でも（calib側の扱い） |

**holdout を見た後に閾値を触ったら、そのホールドアウトは burned。** 作り直すまで
「ホールドアウトで測った」とは言えない。この規律を守れないなら測る意味がない。

分割は**テーマ単位**で行っている。質問単位で割ると同じテーマが両方に入り、
ホールドアウトが「見たことのあるテーマの言い換え」になって評価が甘くなる。

## 標本数の限界（客先説明で必ず必要になる）

0件observedのとき、真の誤回答率について言えることの上限（95%片側）:

| 標本数 | 言える上限 |
|---|---|
| 15問 | 18.1%以下 |
| 30問 | 9.5%以下 |
| 300問 | 0.99%以下 |

**15問で0件を観測しても「誤回答率0%」とは言えない。** 真の誤回答率が10%でも、
15問で0件が出る確率は20.6%ある。客先への説明は測定値だけに依存させず、
「棄却経路ではLLMを一度も呼ばない」という構造的保証を主軸に置くこと。

## 回答不能質問が安いこと

回答可能質問は正解条文の特定が必要（人手・規程受領待ち）だが、
回答不能質問は質問文だけでよく、**判定にLLM呼び出しが1回も要らない**
（ゲート1で落ちるため、cos_max と idf_coverage の計算で結果が出る）。
300問でも埋め込み300回で済む。受入基準が問うているのは回答不能側なので、資源をそちらに寄せる。
