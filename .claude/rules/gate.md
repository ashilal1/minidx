# 二段棄却ゲート（本システムの中核）

`docs/MVP要件定義.md` §3.4 / §5.2 が正本。ここを緩める変更は提案しない。

## ゲート1: 関連性スコア閾値

- 融合スコア最上位が閾値未満なら、**LLM を一切呼ばずに**未整備判定を返す。
  呼ばなければ幻覚は原理的に発生しない。この「呼ばない」ことが実装意図なので、
  「とりあえず投げて LLM に判断させる」形にリファクタしない。
- 閾値は `config.yaml`。評価セットでキャリブレーションする。

## ゲート2: 引用実在性検証

- LLM には `{"sufficient": bool, "answer": str, "citations": [{"regulation": str, "article": str}]}` の
  構造化出力を強制する。
- 生成後、`citations` の各要素が**実際に検索で渡した条文集合に存在するか**を集合照合する。
- 存在しない規程名・条番号が1件でもあれば、回答文の内容にかかわらず**全体を棄却**する。
- **`sufficient` を最終判定に使わない。** これはゲート2への入口にすぎない。

## 生成

- `temperature = 0`。
- コンテキストは検索で得た k=5 件の条文全文のみ。会話履歴や一般知識を足さない。
- システムプロンプトに「提供された条文以外の知識を使わない」「労基法・世間の慣行で補完しない」
  「判断できない場合は `sufficient: false`」を明記する。

## 変更時の義務

検索・ゲート・生成・プロンプト・閾値のいずれかを触ったら、`uv run python -m minidx.eval` を実行し、
**誤回答率 0%** を確認してから完了とする。未実行のまま「問題なし」と報告しない。
